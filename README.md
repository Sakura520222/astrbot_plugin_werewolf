基于 AstrBot 框架的完整狼人杀游戏插件，支持 9 人局、AI 复盘、自动化流程控制，让你在 QQ 群聊中畅玩狼人杀！

> **⚠️ 重要提示**：此插件需要 Bot 账号是群主，因为需要设置管理员、使用禁言和修改群昵称功能。建议将 Bot 设为群主以确保所有功能正常运行。

## 📋 游戏规则

### 默认配置（可自定义）
- **玩家人数**：9 人
- **阵营配置**：3 狼人 + 3 神（预言家 + 女巫 + 猎人） + 3 平民

### 游戏流程
```
夜晚阶段：
  1. 狼人办掉目标（私聊投票，多数票决定）
  2. 预言家验人（私聊验证，得知好人/狼人）
  3. 女巫行动（私聊选择救人/毒人/不操作）

↓

遗言阶段（如果有）：
  - 第一晚被狼杀：有遗言
  - 投票放逐：有遗言
  - 被毒：无遗言

↓

白天阶段：
  1. 公布昨晚死者
  2. 按编号顺序依次发言（每人 2 分钟）
  3. 投票放逐（支持平票 PK）

↓

猎人开枪（如果被杀且可开枪）

↓

判断胜负或进入下一晚
```

### 角色技能
| 角色 | 技能 |
|------|------|
| 🐺 **狼人** | 每晚集体投票办掉一名玩家，可密谋交流 |
| 🔮 **预言家** | 每晚验证一名玩家的身份（好人/狼人） |
| 💊 **女巫** | 拥有一瓶解药（救人）和一瓶毒药（毒人），同一晚不能同时使用 |
| 🔫 **猎人** | 被狼杀或投票放逐时可开枪带走一人，被毒不能开枪 |
| 👤 **平民** | 无特殊技能，依靠推理找出狼人 |

### 弃票与空刀

- 真人和 AI 均可在白天普通投票及 PK 投票时弃票。真人在群里发送 `弃票`（例如 `zx弃票`），也支持 `投票 弃票`。
- 弃票算作已完成投票，但不计入任何候选人的票数；剩余有效票按最高票结算。没有有效票时无人出局，直接进入下一夜；有有效票且最高票相同才触发 PK，PK 再平票无人出局。
- 狼人可私聊发送 `弃票`，也支持 `办掉 弃票`。只统计有效刀票，全部弃票或没有有效刀票则当夜空刀；其余夜间角色仍按顺序行动。
- AI 主动弃票和决策失败降级在内部审计中分别记录；失败或超时只记为弃票，不随机替 AI 选择目标，也不覆盖其他狼人已提交的有效票。
- 结果公告分别列出“弃票”和超时“未投票”的玩家。弃票后的再次提交可在本轮结算前修改选择；结算后不可再更改。

### 胜利条件
- 🐺 **狼人胜利**：好人数量 ≤ 狼人数量，或所有神职出局
- ✅ **好人胜利**：所有狼人被放逐出局

## 🚀 快速开始

### 前置要求
**⚠️ 必须满足以下条件才能正常使用：**
1. ✅ 已安装 AstrBot v4.5.0+
2. ✅ **Bot 账号是群主**（需要禁言和修改群昵称、设置管理员等权限）
3. ✅ 玩家已添加 Bot 为好友（用于接收私聊消息）

### 安装
1. 将插件放入 `data/plugins/` 目录
2. 重启 AstrBot
3. **确保 Bot 在目标群中是群主或管理员**

### 创建游戏
```
1. 房主在群聊发送：创建房间（自动带上你的命令前缀）
2. 9 名玩家依次发送：加入房间
3. 房主发送：开始游戏
4. 游戏自动分配角色并开始
```

## ⚙️ 配置说明

插件配置可在 AstrBot 后台修改：

### AI 配置
| 配置项 | 类型 | 默认值 | 说明 |
|--------|------|--------|------|
| `enable_ai_review` | bool | true | 是否启用 AI 复盘 |
| `ai_review_model` | string | "" | AI 模型 ID（留空使用默认） |
| `ai_review_prompt` | string | "" | 自定义复盘侧重点和详细程度（支持占位符；事实由系统记录生成） |
| `ai_player_model` | string | "" | AI 玩家使用的模型 ID |
| `ai_nicknames` | list | 内置中文昵称词库 | AI 补位随机选名，去重并避开在场玩家；不足时使用不重名的「玩家1」等备用名 |
| `ai_personality_pool` | list | [] | 人格候选 key；留空使用全部内置人格，同局候选用尽后才重复 |
| `ai_personality_overrides` | text | "" | JSON 人格扩展、局部覆盖与权重；`weight: 0` 禁用某个人格 |

AI 补位会跳过空白、超过 10 字和保留名称。手动通过「小咪加入」指定的名称保持不变，不添加表情前缀；同房间已有同名玩家时拒绝添加。开局仍随机分配编号，之后玩家列表按编号升序展示。

发送给 AI 的提示词会移除表情符号。原始日志、发言、讨论、投票和技能经历完整保存；每次调用使用当前轮完整证据、历史摘要索引、最近发言、引用的历史原文及本人私密知识，减少同一论点反复进入提示词。模型输出不会按字符截断。请求超时及游戏操作合法性校验仍保留，提供方的上下文窗口与输出限制仍然适用。

人格与昵称、编号和身份独立，开局固定，贯穿夜间决策、发言、投票及遗言。内置资料位于 [models/personality.py](models/personality.py)：

| 类别 | 人格 key |
| --- | --- |
| 强情绪 | `aggressive` 暴躁、`impulsive` 冲动、`emotional` 感性、`anxious` 焦虑、`competitive` 好胜、`provocative` 挑衅 |
| 低表达 | `quiet` 安静、`terse` 惜字、`shy` 害羞、`timid` 胆小、`cool` 冷静、`calm` 沉稳 |
| 幽默 | `dramatic` 浮夸、`funny` 搞笑、`deadpan` 冷幽默、`sarcastic` 反讽、`playful` 调皮 |
| 推理 | `logical` 逻辑、`rigorous` 严谨、`suspicious` 多疑、`skeptical` 怀疑论、`observant` 观察、`exacting` 较真、`tactical` 战术 |
| 社交 | `enthusiastic` 热情、`easygoing` 随和、`mediator` 和事佬、`empathetic` 共情、`protective` 护短、`curious` 好奇 |
| 主张 | `leader` 带头、`confident` 自信、`direct` 直球、`stubborn` 固执、`rebellious` 叛逆、`contrarian` 唱反调、`independent` 独行侠 |
| 基调 | `adaptable` 灵活、`optimistic` 乐观、`pessimistic` 悲观、`reserved` 内敛、`cautious` 谨慎 |

例如将 `ai_personality_pool` 设为 `["quiet", "logical", "custom"]`，并在扩展字段填写：

```json
{
  "quiet": {"weight": 2},
  "custom": {
    "name": "温和直接",
    "voice": "温和、直说重点",
    "brevity": [20, 60],
    "judgement": "先核对实际原话，再形成判断",
    "risk": "有依据时敢于投少数票",
    "emotion": "被质疑时解释具体事实",
    "weight": 1
  }
}
```

非法扩展项会保留对应内置默认值。候选列表没有可用项时回退到内置人格；人格只改变表达和判断倾向，不能赋予私密信息或改变规则。

| 阶段 | 软性篇幅目标 |
| --- | --- |
| 普通发言 | 通常 25–100 字；低表达人格可更短 |
| 投票理由、狼人密谋 | 通常 15–60 字 |
| PK、直接回应关键指控 | 通常 50–150 字 |
| 遗言 | 通常 30–120 字，完整神职信息优先 |
| 默认复盘 | 选择两三个关键记录和一条建议；自定义提示可要求展开更多记录 |

这些目标均不会触发字符串裁剪。模型先填写内部 `intent`、`reason`、证据编号及行动目标，再给出发送用的 `speech`；内部理由不会自动发送到群聊。投票支持 JSON 协议及原有明确的 `[发言]…[投票]编号/弃票` 协议，不会从普通讨论中的数字猜票。最多三次尝试仍无法形成合法决策时，明确记录失败降级；只有有效的显式弃票才标为主动弃票。运行日志记录状态、目标和尝试次数，完整尝试保存在本局 AI 上下文的 `decision_audit` 中。

公开投票声明会单独核对“我今天投几号”“这一轮我弃票”等明确承诺，区分引述、否定、历史回顾和假设；编号不限定为 1–9。明确冲突时要求模型在原有预算内修复，不能静默改票，也不会裁掉引文或句尾来通过校验。语义不明确时仍以合法的结构化票为提交依据；PK 候选、存活、自投及改票理由限制保持有效。

历史摘要索引标明证据 ID、轮次、类型与发言者。AI 需要核对旧原话时，可先返回 `{"request_evidence_ids":["S1","D2"]}`，回取当前决策开始时已有、本人可见的公开发言/投票讨论原文。每次决策最多补读一轮、三个去重 ID；补读和格式修复共同计入最多三次生成，无补读时不增加调用。补读本身不公开发言、不登记票、不更新立场；未知、私密、未来及第二轮请求会被拒绝。补读后更新实际可引用的证据范围，完整保留原话中的引述、否定和结尾，不将“未展开”误当成“从未说过”。公开发言也须保留二手来源，不能因口语化把转述改成亲口记录。

AI 单次模型请求（含复盘）的等待上限为 **180 秒**。狼人串行密谋、选刀的整体等待预算按 AI 人数、每个行动的最多三次尝试及模拟思考时间计算，避免被较短的整体超时提前取消。房主仍可用 `结束游戏` 取消本局任务。

复盘的选择和格式修复共用 **180 秒总预算**，最多三次生成，不因重试重新计时。超时、不可用或连续返回非法选择时，输出标明来源的系统事实复盘；模型原始回复完整保存在本局 `review_audit`，不直接作为复盘正文发布。

实际请求还受 AstrBot 模型提供方自身的超时设置限制；若提供方小于 180 秒，会先于插件结束请求。

模型调用失败时，普通发言、PK、遗言使用各自的降级表达，结合人格选择并在本局内避开重复句；不会编造查验、用药或其他游戏事实。预言家遗言优先完整保留真实查验记录。正常模型发言也要求用玩家口吻表达，把内部证据术语留在分析字段中。

狼人会分别完整保留本人和队友的密谋原话，不改变已有队友证据编号。主观怀疑度不能覆盖狼人已知阵营或预言家的真实查验；威胁判断、对外假跳与本人真实认知分开记录，冲突的可选判断会被拒绝，但不改动合法投票。信息边界用于内部核对，公开发言不必反复讲规则，也无需等待本局不存在的“全群预言家认证”才作判断。

**自定义提示词占位符**：
- `{winning_faction}` - 胜利阵营（狼人/好人）
- `{game_data}` - 完整游戏数据

## 🔧 技术细节

### 编号系统
- 游戏开始时按本局人数随机分配编号（默认 1–9 号）
- 群昵称临时改为"编号号"（如"1号"、"2号"）
- 游戏结束后自动恢复原昵称

### 禁言机制
- 夜晚阶段：全员禁言
- 发言阶段：当前发言者临时设为管理员，可发言
- 投票阶段：解除全员禁言
- 游戏结束：解除所有禁言

### 超时处理
- 各阶段均有超时机制
- 已死角色的阶段使用随机短时间（10-15秒），避免泄露身份
- 无 AI 时按 `timeout_vote` 等待真人投票；有 AI 时等待当前轮 AI 任务完成后，再等待真人投票窗口
- 满票、超时或重复触发共用一个结算入口，每轮只结算一次；旧轮次和已结束房间的任务不能继续写入

### AI 复盘
- 使用 AstrBot 配置的 LLM 模型
- 记录完整游戏日志（包括狼人密谋）
- 终局胜负、阵营人数及名单由游戏状态生成；关键事实来自带轮次的实际行动日志
- 模型只返回 `highlight_ids` 和 `advice_ids` 选择，系统按原始顺序完整呈现选中记录和建议，不接受额外编写的复盘事实
- 发言、遗言、密谋和主观行动理由仍完整供模型理解上下文，不能被选成已执行动作；未知、重复编号和额外正文会触发修复
- 自定义提示词及占位符保留，用于调整关注点和展开记录数量；自由正文和改写胜负的指令不能覆盖事实协议

### 命令前缀自适应
- 插件启动时自动读取 AstrBot 的 `wake_prefix` 配置
- 所有命令提示、帮助信息都会显示正确的前缀
- 无需手动修改任何配置

## ⚠️ 注意事项

1. **Bot 权限要求（最重要）**：
   - ⚠️ **Bot 必须是群主或管理员**，否则无法使用禁言和修改群昵称功能
   - 建议将 Bot 设为群主以确保所有功能正常运行
   - 如果 Bot 权限不足，游戏将无法正常进行

2. **玩家好友关系**：
   - 玩家必须添加 Bot 为好友才能接收私聊消息
   - 如收不到私聊，可使用 `查角色` 命令（私聊 Bot）查看

3. **游戏稳定性**：
   - 游戏状态存储在内存中，容器重启会丢失
   - 建议游戏进行中不要重启 Bot

4. **配置修改**：
   - 修改配置后需重启插件或容器生效
   - 角色数量必须加起来等于总玩家数（例如：3狼+1预言家+1女巫+1猎人+3平民=9人）
   - 如果配置不正确，插件会自动使用默认配置并在日志中警告

5. **平票处理**：
   - 首次投票平票：进入 PK 环节
   - PK 投票仍平票：本轮无人出局

## 🐛 常见问题

### Q: 收不到角色私聊？
A: 使用 `查角色` 命令（私聊 Bot）查看自己的角色。

### Q: 为什么有时候没有遗言？
A: 遗言规则：
- ✅ 第一晚被狼杀：有遗言
- ✅ 投票放逐：有遗言
- ❌ 被女巫毒杀：无遗言
- ❌ 非第一晚被狼杀：无遗言

### Q: 猎人什么时候不能开枪？
A: 被女巫毒杀时不能开枪（死得太突然）。

### Q: AI 复盘没有生成？
A: 检查配置：
1. `enable_ai_review` 是否为 true
2. AstrBot 是否配置了 LLM 模型
3. 查看日志是否有报错

### Q: 如何自定义游戏人数？
A: 在 AstrBot 后台修改配置，确保角色总数 = 总玩家数。

### Q: AI 讨论超过投票时限，为什么还没有结算？
A: v3.2.0 会等待当前轮 AI 任务完成，避免按不完整票数提前放逐玩家。AI 请求仍有超时和重试保护；房主可用 `AI投票` 复用当前任务，不会重复启动。真人尚未投完时会继续等待对应投票窗口。

### Q: 帮助菜单图片中文显示为方块？
A: v3.0.2 已修复，插件自带中文字体，不再依赖系统字体。

### AI 回归与行为评测

```bash
python -m unittest discover -s tests -v
ruff check . tests/test_issue_3_ai.py tests/test_issue_4_vote_statements.py tests/test_issue_5_evidence_read.py tests/evaluate_ai.py tests/evaluate_game.py

```

确定性测试覆盖动态规则、私密信息隔离、自我编号、时序、人格分配、原文保留、投票声明与结构票一致性、受限历史原文补读、共同调用预算及技能合法性。安装 AstrBot SDK 时，还会测试实际命令处理器。

真实模型评测使用现有 AstrBot 上下文，不在测试文件里放密钥。准备一个 `my_provider.py`，导出 `create(seed)` 并返回实现 `get_using_provider()` / `get_provider_by_id(id)` 的现有模型上下文；如提供方支持种子，应将该种子传给模型。可为工厂函数提供异步 `aclose` 方法清理测试持有的客户端。

```bash
python tests/evaluate_ai.py --provider-factory my_provider:create --seeds 17 43 --output /private/evaluations/samples.jsonl
python tests/evaluate_ai.py --provider-factory my_provider:create --seeds 17 43 --scenarios history_retraction history_clarification --no-matrix --no-mixed --output /private/evaluations/history.jsonl
python tests/evaluate_game.py --provider-factory my_provider:create --seeds 17 43 --output-dir /private/evaluations/games
python tests/evaluate_game.py --provider-factory my_provider:create --all-ai --seeds 43 --output-dir /private/evaluations/all-ai
python tests/evaluate_game.py --provider-factory my_provider:create --review-only /private/evaluations/games/game-17.json --output-dir /private/evaluations/games
```

`evaluate_ai.py` 保存固定场景、42 种人格的发言/投票/遗言及两轮公开阶段回放。`evaluate_game.py` 在安装了 AstrBot 的环境运行真实阶段和命令处理器，使用一名脚本真人与八名 AI；平台发送、禁言及管理员操作全部替换为本地捕获，最多运行指定的轮数。完整提示词、模型原始回复、重试、票和技能记录均保存到指定目录，不做字符截断。

`history_retraction`（跨轮改口）与 `history_clarification`（跨轮澄清）各用两个种子生成四份样本，涵盖旧原话被索引省略、最新无关发言与超过 100 字的尾部否定。固定场景的投票经过实际投票 worker，保存 `submitted_vote`、捕获的公开消息及完整补读/修复审计，供人工逐一核对最终公开话语、结构票和实际提交票；不强制模型得出相同阵营或投票结论。默认不连接任何提供方，真实模型评测必须由传入的现有上下文工厂执行。

`evaluate_game.py --all-ai` 使用九名 AI，经过实际开局指令分配编号、角色与人格，自动走完夜间、遗言、发言、普通/PK 投票、胜负与复盘，并等待房间清理结束。默认不按天数提前截停；可用 `--max-rounds` 指定上限（0 表示直到胜负），`--watchdog-seconds` 设置独立的整局安全预算（全 AI 默认四小时，混合对局默认十五分钟）。逐次完整调用即时保存为同名 `.calls.jsonl`，完整 `.json` 记录持续检查点，异常或中断时保留现场；平台发送与禁言等操作均为本地捕获。

输出含角色秘密，建议放在私有且不提交 Git 的目录。解析通过只说明输出合法，仍需检查声明是否被当成事实、本人记忆、用药/查验时序、改票理由、重复表达与人格差异。公开阶段回放不等于完整流程模拟，隔离模拟也不等于真实群聊联调。
